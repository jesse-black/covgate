## Review
- [ ] Retracted finding: I initially flagged the missing `Subtract` in `tests/fixtures/dotnet/basic-fail/repo/src/CovgateDemo/MathOps.cs` because the ExecPlan step says to add it to both `repo/` and `overlay/`. On re-review, the uncommitted overlay change is what makes `Subtract` a changed uncovered function for diff-scoped function gates; adding the same method to `repo/` would likely remove it from the changed-line diff and undermine the test scenario. The implementation is coherent here, and the plan step appears stale or overspecified.
- [ ] Finding: `cargo xtask regen-fixture-coverage dotnet/basic-fail` produced `tests/fixtures/dotnet/basic-fail/native-summary.json`, but that generated artifact is untracked. Evidence: the file exists with branch totals `1/2` and line totals `4/9`, `git status --short` reports it as `??`, and `git ls-files 'tests/fixtures/dotnet/*/native-summary.json'` does not include `dotnet/basic-fail`. Either the regenerated artifact should be checked in or the regeneration path should not leave this fixture dirty; otherwise rerunning the documented xtask is not idempotent from a clean tree.
- [ ] Finding: The plan did not apply the `docs/TESTING.md` mixed-inline-test rule to `src/coverage/coverlet_json.rs` and `src/coverage/llvm_json.rs`. Evidence: TESTING.md says that when a file has a mix, only private-access tests stay inline and the rest move to `tests/`; `coverlet_json.rs` imports private `normalize_path` but most tests call only `parse_with_repo_root`, and `llvm_json.rs` imports private `normalize_path` / `normalize_llvm_function_name` but many parser-behavior tests call only `parse_with_repo_root` through `parse_str`. Scoping both files out wholesale because they contain some private-helper tests misses the core principle this ExecPlan is meant to enforce.
